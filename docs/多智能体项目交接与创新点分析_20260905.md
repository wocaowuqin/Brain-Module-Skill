## 1. 项目现状与选题判断

**项目已经有较完整的研究平台，但尚未形成“学习算法在公平比较下稳定优于强基线”的证据闭环。** 最有价值的现成基础包括：完整 SFT 候选生成、请求级联合调度、有向资源账本、状态版本检查、迁移事务，以及 Ryu/Mininet 执行和探针接口。下一步应围绕一个可被证伪的问题形成算法贡献，而不是继续增加模型名称。

目前最值得优先研究的是：**存在批内资源冲突时，如何让价值学习、联合可行性解码和实际执行保持一致，并在有限决策时间内获得超过强启发式的收益。** 这个问题可直接复用主代码链，且有明确的当前性能边界。若更偏向“重配置”论文，则优先研究**剩余生命周期与预测不确定性约束下的迁移决策**，但需先补齐动作影响未来状态的环境。[E03–E08]

三个必须先明确的事实：

- 3097 条在线请求全部接受的保存结果中，`wqmix_checkpoint=null`，实际排序器是 `BatchedHRLPolicyRanker`。这是批量 HRL 策略评分与账本准入结果，不是 WQMIX 优势证据。
- 五个测试 seed、500 条请求的保存比较中，WQMIX 和 `joint_greedy` 都接受 439 条。WQMIX 的决策 P95 约 1.56 ms，joint-greedy 约 0.34 ms；这组数据尚未体现额外学习成本带来的接受率收益。
- 中央大脑仍为 `RuleBasedBrainAgent`。部署、迁移、重路由角色及 Skill 协议已经实现，但“中央大脑经过训练”及“三角色共同端到端学习”尚未得到当前主链证据支持。[E01–E03]

最近完成的 Germany50 五个 HRL 变体打包属于单请求 HRL 基线/消融交付。它与请求级 WQMIX 联合调度是不同实验层次，不能把那 30 组 HRL 实验直接当成多智能体协作实验。

## 2. 研究任务与三种多智能体含义

### 2.1 任务对象

一个请求包含源节点、多个目的节点、按顺序处理的 VNF 序列、资源需求及生命周期。系统要生成完整服务功能树：从源经过有序 VNF 阶段，再到达所有目的端；同时满足 CPU、内存和每条有向链路的带宽约束。部署后还需处理热点、SLA 风险、迁移和树重路由。

成功不能只看“找到一条路”或“放置了 VNF”。完整映射、资源准入、真实执行、探针测得的 SLA 是四个不同层次。尤其要区分已启动请求中的条件 SLA 成功率与以全部到达请求为分母的端到端 SLA 成功率。[E09]

### 2.2 不能混为一谈的三条算法线

| 算法线 | 智能体是谁 | 动作是什么 | 当前定位 |
| --- | --- | --- | --- |
| 早期 Role-MARL | SFT 选择、VNF 迁移、树重路由三个固定角色 | 选择目标 SFT、执行迁移/重路由候选或不动作 | 独立 DQN / QMIX 原型；默认配置仍为 independent_dqn |
| 请求级部署 WQMIX | 同一微批中的每个待部署请求 | 选择一个完整候选或 reject | 当前联合准入与调度主线 |
| 中央大脑与专业角色 | Brain + Deployment / Migration / Reroute | 分派事件、调用 Skill、返回提案并仲裁执行 | 当前 Brain 为规则策略；角色接口不等于角色均已学得策略 |

迁移 WQMIX 另以“被选中的 VNF 迁移任务”为临时智能体，动作是完整目标 DC 方案或 no-migration。部署和迁移 checkpoint 类型不同，不可互换。物理节点不是上述请求级 WQMIX 的智能体，拓扑扩大不会自动把智能体数变成物理节点数。[E01、E06、E10]

### 2.3 当前主链与实际运行边界

```text
请求到达 / 生命周期事件
    → 规则中央大脑派发任务
    → HRL rollout，或完整候选生成 + 批量 HRL 策略评分
    → 可选 WQMIX 候选排序
    → 有时间/候选预算的联合可行性解码
    → 版本校验 + 原子资源提交
    → 导出完整计划
    → Ryu/Mininet 执行 + VNF Agent + UDP SLA 探针
    → 可选迁移 / 重路由
```

必须区分两种 HRL 路径：`legacy` 模式执行有状态双层 rollout；`batched-policy` 模式用已有编码器及高低层策略给纯函数生成的完整候选评分，保存结果明确写有 `rollout_vectorized=false`。后者不能描述成已经把完整 HRL 环境交互向量化。

`run_multiagent_online.py` 已能串接规划层的候选、可选 WQMIX 与账本；它不包含数据面 SLA 测量。真实执行入口中的在线 HRL、在线 WQMIX、预生成计划仍有模式互斥关系。当前应表述为“规划层闭环已存在，数据面可阶段式接入”，不能笼统宣称所有环节已在同一进程端到端联训或在线串联。[E02、E09、E11]

### 3.1 WQMIX 实际做了什么

请求 Q 网络输出每个候选的偏好，mixer 在集中训练时估计联合价值。当前 `WeightedQMIXLearner` 在联合 Q 低估 TD target 时使用权重 1，其余样本使用 alpha；损失为加权 Smooth-L1，可叠加 teacher action 的交叉熵。宜称为 OW-QMIX 风格实现，不应未经对照就声称完全复现了原论文全部机制。

在线执行不直接接受各请求 argmax 的组合，而是再经联合解码器。单请求 action mask 只能证明候选各自可行，不能保证多个候选合起来不争抢同一资源。真正的硬约束由联合解码和 `commit_exact` 兜底。[E04、E05]

### 3.2 资源账本中的研究价值

账本按有向边计费；同一 `(node, vnf_type)` 的活跃实例可以共享 CPU/MEM。共享实例意味着多个请求的资源代价不能简单相加。联合提交还检查 snapshot version，过期方案应重新解码，不能部分写入。迁移先准备新路径/实例、维持新旧状态重叠，再切换并释放旧资源，因此迁移可行性比“最终状态能放下”更严格。

这些是有价值的工程及建模基础，但“用了原子事务、mask 或 make-before-break”本身不自动构成算法创新。需要提出可量化的机制，例如冲突结构如何进入价值估计、重叠预留如何影响长期迁移收益。[E04–E07]

## 5. 创新前需要解决的证据缺口

### 5.1 价值备份与执行动作可能不一致

`WeightedQMIXLearner.train_step` 的下一动作通过逐智能体 masked argmax 产生，再送入 target mixer；该处没有调用联合解码器。实际部署则执行经过联合可行性解码后的动作。若各局部最优争抢资源，TD target 可能对应实际不可执行的组合。

这是代码级可定位的研究问题，并非本次已经证明的性能缺陷。应先统计独立 argmax 的联合冲突率、解码改动率和 target 偏差，再检验是否需要解码一致的备份。尤其不能沿用“训练和线上都用了同一解码器”就推断所有学习目标也一致。[E04、E05]

### 5.2 解码器可能解释了大部分收益

现有解码器优先最大化接受数，分数次之；当前 WQMIX 与 joint-greedy 接受数相同。因此算法贡献必须用“固定相同候选、相同解码预算、仅替换排序器”的实验隔离。还需测试关闭 WQMIX safety guard，否则结果可能来自基线回退，而非学得的排序。[E03、E05、E11]

### 5.3 迁移环境还不是完整的策略依赖动态环境

`MigrationWQMIXEnv.step_rankings` 对当前候选计算奖励后递增记录索引；下一观测来自保存的下一条记录，所选动作不会在这个离线环境中改写后续快照。它可做记录回放和当前候选比较，但不足以研究迁移改变未来拥塞、实例复用和反复迁移的长期价值。[E06]

当前迁移奖励对 no-migration 使用 `-1 - 2×sla_risk`，可行迁移则包含固定 SLA 正奖励及较小的迁移耗时惩罚。这是应做敏感性分析的取舍：若场景中迁移本无必要，固定不动作惩罚可能使策略过度迁移。应以相同未来负载下的增量收益、剩余寿命和中断成本验证，不能只看奖励变高。[E07]

### 5.4 Telecom Italia 支线有前视信息

`simulator.py` 的 `brain_rule_marl` 在迁移选择时调用 `sfc.flow(slot + offset)` 读取未来窗口峰值；`_forecast` 用全曲线最大值限幅；归一化分位数也来自整段曲线，早期历史索引使用循环取模。因此当前结果应标作含已知轨迹信息的规则回放，不能作为严格因果预测式 MARL 成果。

应将未来峰值版本单列为预知未来的参考对照；在线版本仅使用决策时刻之前的数据，归一化参数在训练时间段固定，序列开始处不得以末尾样本补历史。已有 24 行 gated 汇总的 SLA satisfaction 均为 1.0，说明该 SLA 指标在这组模型参数下缺乏区分度。[E15、E17]

### 5.5 架构与结果的可追溯性不足

8 月 26 日交接文档、8 月 30 日在线文档和当前交付 README 存在时间差。旧文档中的失败 checkpoint、后续 mask-fix 计划和批量评分结果不能相互覆盖；在线报告还记录了外部 `Desktop/hrl` 目录。发表前需冻结每次实验的代码哈希、候选生成模式、模型、原始 trace 和 profile，避免两个 HRL 目录的行为混用。

## 6. 值得优先检索和验证的创新方向

以下方向按与现有主线的衔接程度排序。每个方向都需要查新，且应保留“强启发式已经足够好”的否定结果。

### 方向 A：联合可行性感知的价值学习（优先）

**问题：** 单个候选可行不代表联合动作可行；局部 TD 备份与接受数优先的解码可能优化不同对象。

**可提出的机制：** 用候选资源 footprint 构建请求冲突关系；在训练中以同一预算下的联合解码动作计算下一状态价值，或让 critic 学习“经过解码后”的价值。若加入冲突图编码，需要证明其解决的是跨请求竞争和共享实例，而非仅增加参数。

**最小验证：** 固定 Top-K 生成器、训练数据、网络规模和解码预算，对比原 WQMIX、解码一致备份 WQMIX、joint-greedy、BC 以及小批次候选域精确求解器。设置批大小 1/2/4/8/16，并控制资源重叠率；同时报告接受率、每请求效用、联合冲突率、解码改动率和决策 P95。

**否定条件：** 在相同预算及相同候选下，学习法仍不能超过 joint-greedy，或收益仅来自更长搜索，则不支持该算法贡献。此时可将它保留为诊断结果，不应通过削弱基线制造差距。

**检索词：** constrained cooperative MARL；action correction/shielding；feasible Bellman backup；value factorisation with coupled constraints；learning to optimize SFC admission。

### 方向 B：截止时间约束下的自适应微批与候选预算

**问题：** 5 ms 窗口在低到达率下几乎没有多智能体；扩大窗口虽可能提高协调机会，也增加等待、快照过期和请求来不及启动的风险。

**可提出的机制：** 根据队列长度、请求剩余截止时间、预测资源冲突和解码耗时，联合选择微批窗口、Top-K/Top-R 或计算预算。目标应是截止时间内的有效准入/完成效用，计入排队与决策时间，而非单独最大化回放吞吐。

**最小验证：** 与固定窗口网格、即时逐请求、最早截止时间优先、固定自适应阈值启发式比较。对泊松、突发和长短寿命混合到达做同 trace 配对测试；统计等待 P95、规划 P95、截止时间前启动率、冲突率、版本重试和端到端 SLA。

**否定条件：** 简单阈值调度已达到相同效用，或所谓收益来自提前读取未来 trace，则不足以支持学习调度的必要性。

**检索词：** deadline-aware online batching；adaptive inference scheduling；resource-constrained admission control；anytime combinatorial optimization。

### 方向 C：生命周期与不确定性感知的预测迁移（重配置论文优先）

**问题：** 短寿命服务可能在迁移收益兑现前离开；错误预测可能增加迁移、中断和资源重叠，甚至导致来回迁移。

**可提出的机制：** 预测未来负载及不确定性，以剩余寿命内预期拥塞/SLA 损失的减少，抵扣状态传输、临时资源预留和中断成本；允许有意义的不动作。中央策略决定是否触发与资源预算，任务级策略选择迁移对象和目标，安全层保留确定性约束。

**前置工作：** 建立动作会改变后续放置、实例引用、带宽和队列的动态环境；把未来流量隔离为外生 trace；修正 Telecom Italia 前视信息，按不同日期/请求 seed 划分训练验证测试。现有记录回放环境不够。

**最小验证：** no-migration、reactive、causal predictive heuristic、WQMIX、生命周期门控、风险门控及其消融。用未来已知的规划器只作上界参考。指标包括过载面积、有效服务时长、中断、迁移数、反复迁移率、能耗和增量成本，并做多种预测误差测试。

**否定条件：** 去掉学习仅保留冷却期和寿命阈值就得到同等收益，或只改善手工奖励而损害服务质量，则创新应归因于门控机制或重新选题。

**检索词：** uncertainty-aware VNF migration；remaining service lifetime；counterfactual migration benefit；safe hierarchical MARL；make-before-break resource reservation。

### 方向 D：学习式中央大脑与跨操作协作（成本较高）

**问题：** 部署、迁移、重路由处于不同时间尺度；规则路由未学习何时该迁移、何时只重路由，以及两者的冲突。

**可提出的机制：** 在共享系统状态上学习事件调度或 option 选择；专业角色产生候选，由仲裁器保证安全。先保持“同一 SFT 每轮单个安全动作”，验证学习触发是否有增益，再考虑迁移与重路由的联合事务。

**必须比较：** 当前规则 Brain、平面单智能体策略、学习 Brain + 固定专业策略、完整层次策略。奖励需包含长期服务效用与执行失败，训练数据必须有动作后的真实状态演化。

**风险：** 只把类名改成 Agent、接入一个 PPO、或把 Skill 注册表包装成“智能体框架”，不构成足够研究贡献。跨操作原子事务目前尚未实现，这条路线的实现和归因成本最高。[E01]

### 6.5 建议的选题组合

若希望最快形成可检验的算法论文，选择 **方向 A 为主，方向 B 作为系统预算约束**；第一步先证明冲突数据上存在超越 greedy 的空间。若论文明确围绕 VNF 重配置，选择 **方向 C 为主**，Brain 先保留规则，避免同时训练多个尚不稳定的层。方向 D 暂作后续扩展。

候选题目可写为：“面向动态多播服务功能树的联合可行性感知多智能体调度”或“面向服务剩余生命周期的风险约束预测式 VNF 迁移”。这只是工作题目，不代表已完成新颖性认定。

## 7. 实验路线与交接操作

### 7.1 建议按四个门槛推进

| 阶段 | 要回答的问题 | 最小交付物 |
| --- | --- | --- |
| 证据冻结 | 实际跑的是哪条链、哪个模型、什么数据？ | 源码/模型/trace/profile 哈希；候选来源统计；配置与命令 |
| 难点确认 | 当前任务是否存在足够多的协作冲突或长期迁移收益？ | 批大小分布、资源冲突率、greedy 与候选域上界差距 |
| 单机制验证 | 新机制贡献能否脱离候选生成、解码预算和回退策略单独成立？ | 同候选、同预算、同 seed 的主比较及消融 |
| 泛化与执行 | 是否跨 seed/日期/拓扑成立，并能转化为实际服务收益？ | 配对置信区间、未见场景测试、小规模 Mininet 实测 |

正式结果以独立训练 seed 为重复单位，测试 trace 做配对；先报告均值、95% 置信区间和效应量，再决定是否做配对显著性检验。不要把同一策略中的每个请求都视为独立训练重复，也不要用相邻窗口随机拆分替代跨日期验证。
